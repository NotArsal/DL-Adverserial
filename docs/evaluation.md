# Evaluation & Limitations

This document outlines the measured performance of the FaceGuard swap detector against live presentation attacks. All metrics are derived from the raw JSON outputs located in `eval_results/`.

## The Threat Model

The primary threat model for this system is a **live presentation attack**. In this scenario, an attacker feeds a real-time face-swap (generated by tools like InSwapper or Deep-Live-Cam) directly into a camera stream to impersonate an enrolled user.

* **Defended**: Live face-swaps presented to the camera.
* **Not Defended**: White-box digital perturbations (adversarial noise injection), alternative swap models not represented in the training data, and physical replay/print attacks.

## Baseline Vulnerability

Without a dedicated defense mechanism, standard facial recognition is highly vulnerable to face swaps. When tested against InSwapper face swaps on held-out pairs, the ArcFace identity matching model accepted the swapped face as the target identity **99.6%** of the time.

## Defense Efficacy

We trained a custom MobileNetV2 swap detector to run concurrently with the identity matcher.

### Non-Adversarial Setting (Presentation Attacks)

When evaluated on identity-disjoint test data (LFW people and FaceForensics++ videos not seen during training):

| Operating Threshold | Swaps Detected | Real Users Falsely Blocked |
|---------------------|----------------|-----------------------------|
| 0.8                 | 90.5 %         | 1.1 %                       |
| 0.5                 | 94.7 %         | 4.2 %                       |
| **0.3 (Deployed)**  | **96.2 %**     | **6.1 %**                   |

End-to-end, integrating the detector drops the attack success rate from 99.6% down to approximately 4-5% per frame.

### Temporal Smoothing

Because webcam feeds exhibit domain shifts (lighting changes, motion blur), a single-frame threshold of 0.8 often misses live swaps. To account for this, the deployed system uses a lower threshold (0.3) combined with **temporal smoothing**. The system calculates the mean of the top-2 anomaly scores over the last 8 frames and requires a minimum of 3 frames before issuing a verdict. This significantly stabilizes the defense in a live environment.

## Known Limitations

While highly effective against standard presentation attacks, the current detector focuses on practical real-time detection rather than theoretical adversarial robustness. In controlled white-box testing, carefully crafted gradient-based perturbations (e.g., L∞ attacks) can bypass the detector. Hardening the model against digital-injection adversarial attacks remains an area for future research.
